X-Safe 开发文档

面向开发者与维护者：模块架构、关键流程、PyInstaller 打包与版本历史。

项目简介

X-Safe 安全中心 是 Windows 上的主动防御型杀毒软件， 核心思路是「先弹窗、再处置」——特征查杀、AI 行为评分、云端联动和系统敏感点监控都在一个中文界面里。

技术栈：Python 3.13+ · tkinter GUI · watchdog 文件监控 · pystray 系统托盘 · 纯标准库 + 少量 pip 依赖，可经 PyInstaller 打包为单目录 exe。

快速开始

从源码运行

git clone https://github.com/max257026-svg/X-Safe.git
cd X-Safe
python -m venv .venv
.venv\Scripts\activate        # Windows
pip install -r requirements.txt
python main.py

从源码打包成 exe

pip install pyinstaller
rm -rf build/ dist/           # 必须清缓存，否则可能用旧代码
pyinstaller main.spec --noconfirm --clean
PyInstaller 缓存陷阱：每次改完代码后必须 rm -rf build/ dist/，否则可能用旧代码打包。

关键流程

1. 快速扫描流程

用户点击「快速扫描」按钮
  ↓
_start_quick_scan()  (main.py)
  ↓
_start_scan_thread(scan_fn)  ── 启动后台线程
  ↓
scanner.quick_scan()  (engine.py)  ── 逐文件扫描
  ↓
self._on_scan_progress(result, stats)  ── 每次发现可疑
  ↓
self._scan_queue.put(("progress", result, stats))  ── 跨线程安全
  ↓
主线程 _process_scan_queue()  ── 30ms 轮询
  ↓
_dispatch_scan_event("progress") → _update_scan_ui(...)
  ↓
if result.is_threat:  _add_result_to_tree / _show_threat_toast
  ↓
_show_scan_summary_toast(result)  ── 累积摘要弹窗（1.5s 节流）
  ↓
ThreatToast 弹窗（屏幕右下方）

2. 实时防护触发流程

watchdog 检测到文件创建/修改/移动
  ↓
FileMonitor._on_modified(event)  (monitor.py, 子线程)
  ↓
判断路径是否值得关注
  ↓
scanner.scan_file(file_path)  ── 同步扫描单个文件
  ↓
OnThreatDetectedCallback(result)  (main.py)
  ↓
self._scan_queue.put(("threat", result))  ── 跨线程
  ↓
主线程 _process_scan_queue() → _show_threat_toast  (每个威胁一个)

3. ThreatToast 弹窗系统

累积摘要弹窗（手动扫描时使用，避免 500+ 弹窗被 max_toasts 顶掉）：

def _show_scan_summary_toast(self, result):
    self._scan_acc_count += 1
    self._scan_acc_samples.append(result)
    if now - self._last_scan_summary_toast_ts < 1500:
        return  # 仅累积，不弹
    self._toast_manager.clear_all()
    config = ToastConfig(
        title=f"扫描发现 {count} 个威胁",
        details="前几个样本...",
        auto_dismiss=0,
    )
    self._toast_manager.show_toast(config)

单条带按钮弹窗（实时监控时使用，每个威胁一个，带删除/自检/忽略回调）。

运行时读写

线程模型

线程职责创建位置
主线程 (Tk)UI 渲染 + 30ms 轮询 _process_scan_queuetkinter
扫描线程快速/高级/自定义扫描，逐文件调 _on_scan_progress_start_scan_thread
文件系统监控线程watchdog 监听（每个路径一个 Observer）monitor.py:FileMonitor.start
注册表监控线程轮询关键项变化registry_monitor.py:RegistryMonitor.start
进程监控线程轮询进程启动/退出process_monitor.py:ProcessMonitor.start
UI 轮询线程 (after)1000ms 检查 result_tree 新增行self.root.after(1000, ...)

跨线程通信

  • 扫描线程 → 主线程：_scan_queue: queue.Queue（先进先出）
  • 监控线程 → 主线程：通过 _scan_queue 推 ("threat", result) 事件
  • 主线程 → 子线程：无；扫描取消通过 threading.Event
关键原则：任何 UI 操作必须在主线程；任何 tkinter 变量读取必须在主线程；后台线程绝不能调用 tkinter API（否则报 main thread is not in main loop）。

关键设计决策

1. 累积摘要弹窗（手动扫描）

问题：快速扫描发现 500+ 威胁时，30ms 内创建 500+ ThreatToast，被 max_toasts=8 顶替后用户看不到。

方案：手动扫描时只弹 1 个累积摘要（每 1.5s 更新一次），弹窗前 clear_all() 清空队列。

2. 不自动隔离

问题：用户希望对威胁有最终决定权，自动隔离是过度保护。

方案：检测到威胁 → 弹 ThreatToast → 用户选「删除/隔离/自检/忽略」。

3. 自保护白名单

问题：PyInstaller 打包的 _internal 目录被扫描器误报，导致程序无法运行。

方案：WhitelistEngine.is_self_protected(path) 检查 sys.executable 和 _internal 目录，默认豁免。

4. 数据目录在 %TEMP%

问题：%APPDATA% 在公司/家庭策略下可能被静默重定向到 exe 同目录。

方案：用 %TEMP% 替代 %APPDATA%，跨用户稳定可写，不受策略限制。

5. after 链不断裂

问题：self.root.after(1000, self.method) 传 bound method，Tk 注册成临时 command，GC 后失效。

方案：用 _poll_tick_wrapper() 包装函数 + lambda: self._poll_tick_wrapper() 保引用。

快速打包

# 1. 清理旧 build（必须！PyInstaller --clean 不会清 build/ 目录）
rm -rf build/ dist/

# 2. 打包
pyinstaller main.spec --noconfirm --clean

# 3. 输出位置
# dist/XSafe/XSafe.exe        — 主程序
# dist/XSafe/_internal/        — 依赖库
# dist/XSafe/signatures.json   — 病毒签名
# dist/XSafe/xsafe.ico         — 图标

main.spec 配置

main.spec 是 PyInstaller 的打包配置：

datas = [
    ('signatures.json', '.'),    # 病毒签名
    ('ai_learning.db', '.'),     # AI 学习数据库种子
    ('theme_config.json', '.'),  # 主题配置
    ('cloud_cache.json', '.'),   # 云查杀缓存
    ('cloud_config.json', '.'),   # 云查杀配置
    ('hosts_backup.txt', '.'),   # hosts 备份
    ('xsafe.ico', '.'),          # 应用图标
    ('quarantine', 'quarantine'),# 隔离区
]

hiddenimports = [
    'watchdog', 'pystray', 'PIL',
    'self_check', 'boot_guard',
    'registry_monitor', 'winreg',
    # ... 等
]

常见问题

Q1: 打包后启动报 "ModuleNotFoundError: No module named 'xyz'"

原因：模块没在 hiddenimports 列表中。
解决：把模块名加到 main.spec 的 hiddenimports，重新打包。

Q2: 启动后报 "database is locked"

原因：exe 模式的数据目录是 _internal/.userdata 而非 %TEMP%\XSafe。
解决：确认 _get_data_dir() 用了 sys.frozen（不是 sys._frozen），并确认打包时带上了 ai_learning.db。

Q3: ThreatToast 弹窗不显示

原因：① PyInstaller 用了 build 缓存（最常见）；② max_toasts 被狂涌覆盖；③ toast_manager 没初始化。
解决：rm -rf build/ dist/ 重新打包；手动扫描走累积摘要弹窗（v28 修复）；检查 poll_debug.log。

Q4: 实时监控失效

原因：watchdog 子线程 join 卡 UI 线程。
解决：后台 daemon 线程 + PollingObserver 兜底 + try/except 隔离失败路径。

1.0.0 — 2026-07-18（首次发布）

由竹影清风独立设计开发，新启年工作室联合出品。

三引擎联动

  • 特征引擎：哈希签名（MD5/SHA256）+ 模式规则（regex）+ YARA 风格字符串匹配
  • AI 自学习引擎：本地熵值、节区特征、API 调用序列综合评分，结合用户反馈持续学习
  • 云端查杀：360云 + VirusTotal 在线验证，群体判定与最新威胁标签
  • 统一 ConfidenceScore：三引擎结果按权重融合，给出最终风险等级

主动防御

  • 文件系统监控：watchdog（实时）+ PollingObserver（系统目录兜底）
  • 注册表监控：Run / IFEO / Winlogon Shell / AppInit_DLLs / Userinit 关键项
  • 引导区保护：MBR / VBR 哈希快照，发现篡改立即告警
  • 进程行为监控：异常父子进程、DLL 注入、批量加密写文件实时拦截
  • 系统敏感文件监控：hosts、计划任务、启动项、卷影副本、SAM

自检与恢复

  • 自检程序：隔离区完整性 + 引导区 + 注册表基线巡检
  • 勒索恢复：WannaCry / EternalBlue 痕迹检测 + 卷影副本恢复
  • 隔离区：处置后样本落入可恢复隔离沙箱，误杀可一键还原

ThreatToast 弹窗系统

  • 屏幕右下方 420×340 无边框弹窗
  • 累积摘要弹窗（手动扫描）：狂涌 500+ 威胁时每 1.5s 弹 1 个
  • 单条带按钮（实时监控）：删除 / 自检 / 忽略
  • 不自动隔离——用户在弹窗里决定如何处置

UI 设计

  • 浅 / 深双主题，一键切换
  • 左侧直角导航栏 + 大色块按钮
  • 实时防护独立板块（6 子模块开关）
  • 扫描结果区支持全选/单选/删除/隔离/信任/导出
  • 关于页含制作/出品/鸣谢信息

已知限制

  • 仅支持 Windows 10/11
  • 云查杀需要联网（可关闭）
  • 部分核心 API 依赖管理员权限（HKLM 启动项、引导区）
